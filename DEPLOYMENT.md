# Deployment quickstart

The complete, production-grade procedure — including verification, rollback,
custom domains, troubleshooting, and the go-live checklist — is in
**[docs/deployment.md](docs/deployment.md)**. This file is the short version.

**Stack:** Supabase (PostgreSQL) + Render (Docker API) + Vercel (Next.js).
**Cost:** ₹0 recurring for a pilot, with the free-tier caveats below.

---

## 1. Before you deploy

1. Push `main` to GitHub.
2. Choose a **new** production owner email and a strong password. Do not reuse
   the local development account.
3. Generate a `JWT_SECRET` of at least 32 random bytes.
4. Collect the Supabase **session pooler** JDBC URL, username, and password from
   `config/application-local.properties` or the Supabase dashboard.
5. Confirm the API starts locally (Hibernate schema validation must pass).

## 2. Deploy the API (Render)

1. Render → **New → Blueprint** → select `SaGaru007/RoyalTravels`.
2. Render reads [`render.yaml`](render.yaml) and creates `royal-travels-api`
   (Docker, free, Singapore, health check `/api/health`).
3. Fill the prompted secrets:

| Variable | Value |
|---|---|
| `DB_URL` | `jdbc:postgresql://<host>:5432/postgres` |
| `DB_USERNAME` | `postgres.<project-ref>` |
| `DB_PASSWORD` | Supabase database password |
| `JWT_SECRET` | Generated by Render, or 48+ random characters |
| `ADMIN_EMAIL` | New production owner email |
| `ADMIN_PASSWORD` | New strong password |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:3000` for now |

4. Deploy and wait for `Started RoyalTravelsApplication`.
5. Open `https://<service>.onrender.com/api/health`; expect
   `{"status":"ok","database":"up"}`.

## 3. Deploy the frontend (Vercel)

1. Vercel → **Add New → Project** → import the repository.
2. Framework: **Next.js**. **Root Directory: `frontend`**.
3. Add:

```text
NEXT_PUBLIC_API_BASE_URL=https://<service>.onrender.com
```

4. Deploy. Copy the production URL.

## 4. Allow the frontend origin

Render → Environment:

```text
CORS_ALLOWED_ORIGINS=https://<your-project>.vercel.app
```

Save and redeploy the API. Use the exact origin, no trailing slash.

## 5. Verify

| Check | Expected |
|---|---|
| `GET /api/health` | `200`, database `up` |
| `GET /api/vehicles` | Six seeded vehicles |
| Homepage / `/fleet` / `/track` / `/driver/trip` | Load without console errors |
| `/admin/login` with the new credentials | Dashboard loads |
| One real booking end to end | Booking → assign driver → trip sheet → completed |

Full 43-check suite (staging only, it inserts rows):

```powershell
$env:API_BASE_URL="https://<service>.onrender.com"
$env:ADMIN_EMAIL="owner@yourdomain.com"
$env:ADMIN_PASSWORD="your-production-password"
node scripts/e2e-smoke.mjs
```

Clean up afterwards with `psql "$env:DB_URL" -f scripts/cleanup-test-data.sql`.

## 6. Keep it warm

Create a free monitor at cron-job.org or UptimeRobot:

```text
GET https://<service>.onrender.com/api/health   every 10 minutes
```

Render free sleeps after ~15 idle minutes; the first request then takes 30–90
seconds.

## 7. Immediately after launch

- [ ] Change the owner password at `/admin/settings`.
- [ ] Add real drivers and review the fleet.
- [ ] Rotate the Supabase password if it was ever shared.
- [ ] Publish Privacy, Terms, and Refund pages.
- [ ] Take the first backup.
- [ ] Add a custom domain and update CORS.

## Free-tier notes

| Piece | Limit | Consequence |
|---|---|---|
| Render | 512 MB, sleeps after ~15 min | Cold starts; JVM heap tuned in `render.yaml` |
| Supabase | 500 MB, limited backups | Manual exports; project may pause when idle |
| Vercel Hobby | Non-commercial use | Use Pro or Cloudflare Pages for a commercial site |
